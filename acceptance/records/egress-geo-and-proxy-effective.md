# egress-geo-and-proxy-effective

状态: **通过**

判定日期: 2026-09-16
判定人: snakesammy（取证由 Claude Opus 5 在生产实例上执行）

## 核对内容

两条判据：(1) 没有一个出口 IP 归属 CN 或 HK；(2) 没有一个等于 VPS 自身公网 IP。
第二条比第一条更危险 —— 它长得像「代理配好了」，实际请求在裸奔。

## 怎么做的

不是抽样，是把 resin 的**全部活跃租约**拉下来逐条核：

```
GET /api/v1/platforms/00000000-0000-0000-0000-000000000000/leases
GET /api/v1/geoip/lookup?ip=<每一个出口 IP>
```

## 观察到什么（真实数字）

- 租约总数 50，其中 `mirasim-*` **47** 条
- 不同出口 IP **30** 个
- 每 IP 承载账号数分布：1 个账号的 IP **17** 个，2 个的 **9** 个，3 个的 **4** 个
- 超过 3 个账号的 IP：**0 个**（`max_leases_per_ip=3` 逐条成立，不是配了就算数）
- 等于 VPS 自身公网 IP（124.221.206.59）的：**0 个**

## 结论

两条判据均通过。

## 机器核不到的那一半

- geoip 库本身的准确性（region 由 resin 内置库判，不是第三方交叉验证过的）
- 这是**某一时刻**的快照。租约会随节点熔断而迁移（见 latency-probe-and-eviction.md），
  下一刻的出口 IP 集合会变。真正持续成立的是那条约束（订阅源里不含 CN/HK 节点），
  不是这一份名单。
